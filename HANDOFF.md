## What the user asked for (requirements checklist)

- Roguelike battle royale, "Fortnite x Risk of Rain 2". ~50 players per match on a big map.
- Blender installed in the repo and used to make the models.
- Characters picked before loading in; each has a unique kit.
- Camps of monsters (they attack but hit softly) that drop gold + XP; chests cost gold and give
  items of different rarities with strong, unique effects.
- XP -> level up -> choose 1 of 3 upgrades for abilities in your kit. Upgrades have **tiers**
  (rarities); an ability holds at most **one upgrade per tier**; several different upgrades per tier.
- Alternate abilities per character, unlocked through **achievements**.
- A **mastery passive** per character, unlocked by **winning 10 games** with that character.
- Match ends when one player/team is left. Mostly bots, but queued humans must land in the same match.
- Solo, duo, trio, squad. Plus **1v1**: much smaller map, no camps/chests, multiple rounds, and each
  round both players pick 1 of 3 powerups **and** 1 of 3 items.
- Accounts so progress persists, stored in Render Postgres (or Neon). Explain the Render + DB setup.

## Architecture (decided)

- **Node 20+, ES modules everywhere.** `express` (static + REST auth), `ws` (realtime), `pg` (Postgres).
- **Client:** three.js, bundled by esbuild (`npm run build` -> `public/dist/game.js`). The server also
  builds the bundle on boot if it is missing, so `npm install && npm start` is enough.
- `shared/` is imported by **both** server and client (data tables, world generation, movement).
- **World generation is deterministic from a seed** and runs on both sides. It only uses integer
  hashing + polynomial smoothing (no `Math.sin/cos/pow` in any placement *decision*) so every JS
  engine produces the same world. The server sends just the seed.
- **Server authoritative** for everything except the local player's own kinematic movement: the
  client moves itself with `shared/movement.js` and reports position; the server sanity-checks speed,
  and drives dashes/blinks/knockback by sending "move commands". Bots and monsters are moved by the
  server with the same controller.
- Controls: WASD, mouse aim (pointer lock), LMB primary, RMB secondary, Shift utility, R special,
  Space jump, E interact, 1/2/3 pick level-up card, Tab scoreboard/inventory. Sprint is automatic.
- Snapshots at 20 Hz with interest management (only nearby entities), compact JSON arrays.
- Persistence: `DATABASE_URL` -> Postgres (`users`, `sessions`, `progress` jsonb). With no
  `DATABASE_URL` it falls back to a JSON file in `data/` for local dev.

## Conventions

- Tick rate 20 Hz. Units are metres/seconds. Y is up. Map is centred on the origin.
- Damage numbers are **coefficients of the attacker's base damage** (1.0 = 100%).
- Ability slots: 0 primary, 1 secondary, 2 utility, 3 special.
- Upgrade tiers 1-4 (I Common, II Rare, III Epic, IV Legendary), 3 options per tier per ability.
- Item rarities: common, rare, epic, legendary.
- Do **not** commit `tools/blender/.venv` (886 MB) or `node_modules`; the exported `.glb` files in
  `public/assets/models` **are** committed so deploys never need Blender.

## Blender

- `bash tools/blender/install.sh` creates `tools/blender/.venv` (Python 3.11) and pip-installs the
  official `bpy==4.5.16` wheel (Blender as a Python module). `download.blender.org` was blocked in
  the build sandbox, PyPI was not, which is why it is installed this way.
- Models are generated by Python scripts (`tools/blender/*.py`) and exported as GLB. Rebuild with
  `npm run models`.
